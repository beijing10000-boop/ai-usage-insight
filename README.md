# AI 运营洞察平台（ai-usage-insight）

把飞书的 **AI 用量**同步到自己的服务器上，回答四个问题：**用了多少、谁在用、用在哪里、有没有异常**。

飞书管理后台能看到 AI 用量，但数据分散、不能按自己的组织口径汇总，也没法分给各部门负责人自己看。这个平台通过飞书开放平台的
「AI 用量日志」「AI 用量统计详情」两个接口把数据拉下来，提供驾驶舱、部门运营、个人用量、额度对账、周报推送，以及给 AI 工具用的开放接口和 MCP。

功能参考了飞书的《AI 运营洞察平台》方案（部署在妙搭里的版本），这里是一个**可以自己部署的独立实现**：一个 Docker 容器、一个 SQLite 文件，不依赖妙搭。

## 功能

| 页面 | 做什么 | 谁能用 |
|---|---|---|
| AI 门户 | 用一句话提问（「哪些部门增长最快？」），助手按你的数据范围取数后回答；首页同时给出关键指标和异常线索 | 所有人（各自的数据范围） |
| 运营驾驶舱 | 总用量、折算费用、活跃人数、趋势、异常提醒、一级部门汇总与下钻、人员 / 应用排行、场景分布、额度类型、使用时段、部门圈选、导出 Excel | 运营管理员 |
| 部门运营 | 一个部门（含下级）的指标、趋势、下级部门、成员用量、场景分布 | 部门负责人、运营管理员 |
| 豆包运营 | 豆包工作的用量：日均活跃、按日 / 周 / 月的用量、活跃人数、人均用量，部门统计与下钻，人员明细，场景分布 | 运营管理员 |
| 用量明细 | 每一次使用的原始记录（人、部门、场景、额度类型、点数、备注）和按天的统计详情，可筛选、导出 Excel | 运营管理员 |
| 我的用量 | 自己每天用了多少、用在哪些场景、每次使用的明细，以及所在部门的整体情况 | 所有人 |
| 额度分配 | 给部门、人员、应用分配周期额度，对照实际用量算已用、剩余、使用率 | 运营管理员 |
| 同步管理 | 测试飞书连接、按日期手动同步（可停止）、每日定时同步、通讯录同步 | 运营管理员 |
| 执行日志 | 每次同步任务的状态、各数据集写入量、接口分页数、失败原因 | 运营管理员 |
| 映射与推送 | 应用名称映射、点数单价、AI 用量周报（飞书卡片）的配置、测试发送与推送记录 | 运营管理员 |
| 接入管理 | 个人访问令牌、开放接口、远程 MCP 的接入说明 | 所有人 |
| 角色权限 / 操作审计 | 运营管理员名单；谁在什么时候做了什么 | 运营管理员 |

两个角色：

- **运营管理员**（`operations_admin`）：全部功能和全量数据。
- **普通用户**（`regular_user`）：自己的用量；通讯录里是部门负责人的，还能看自己负责的部门（含下级部门）。

## 部署

### 1. 准备飞书应用

在[飞书开放平台](https://open.feishu.cn/app)创建一个**企业自建应用**（登录、通讯录、AI 用量都用它），然后：

1. **开通权限**（权限管理 → API 权限，选应用身份）：

   | 权限 | 用途 |
   |---|---|
   | `admin:ai_usage_log:read` | 查询 AI 用量日志。**灰度中**，需要联系飞书客户成功经理申请 |
   | `admin:ai_usage_detail:read` | 查询 AI 用量统计详情。**灰度中**，同上 |
   | `contact:contact.base:readonly` | 读取通讯录 |
   | `contact:department.base:readonly`、`contact:department.organize:readonly` | 部门名称和上下级关系（按部门树汇总要用） |
   | `contact:user.base:readonly` | 把人员 ID 显示成姓名 |
   | `directory:department.leader:read` | 部门负责人（决定谁能看哪个部门） |
   | `admin:app.info:readonly` | 把应用 ID 显示成应用名称 |
   | `directory:department.base:read`、`directory:department.external_id:read` | 可选：让用量日志带上「使用时所在的部门」。不开的话按通讯录里的当前部门算 |
   | `im:message:send_as_bot` | 可选：推送 AI 用量周报。还要给应用开启「机器人」能力 |

   通讯录的**数据权限范围**设为全部员工（范围不够时，部分人员和部门只能显示成 ID）。

2. **安全设置 → 重定向 URL**：填 `<平台访问地址>/auth/callback`，例如 `https://ai-usage.example.com/auth/callback`。
3. **创建版本并发布**。只创建不发布，权限不会生效。

可选：如果想自动解析 Aily 工作流应用和智能体的名称，再在 Aily 开发后台建一个应用，开通 `aily:stats:read`，把它的凭证填到 `AILY_APP_ID` / `AILY_APP_SECRET`。不配也可以，在「映射与推送」里手工填名称。

### 2. 启动服务

```bash
git clone https://github.com/beijing10000-boop/ai-usage-insight.git
cd ai-usage-insight
cp .env.example .env      # 填访问地址和会话密钥就够了，飞书凭证在页面上填
docker compose up -d --build
```

默认监听 8090 端口。`.env` 里必须填的只有两项：

| 变量 | 说明 |
|---|---|
| `AIUS_PUBLIC_URL` | 浏览器访问的地址，不带结尾的 `/` |
| `AIUS_SECRET_KEY` | 会话签名密钥，至少 32 个字符。页面上保存的凭证也用它加密，**定下来就不要再改** |

其余可选项（端口、PyPI 镜像、固定的运营管理员等）见 [.env.example](.env.example)。

### 3. 首次配置（在页面上填飞书凭证）

1. 取初始化口令（证明你是部署这个平台的人，只有能登上服务器的人拿得到）：

   ```bash
   docker compose exec ai-usage-insight cat /data/bootstrap.token
   ```

2. 浏览器打开 `<平台访问地址>/setup`，填初始化口令、飞书应用的 **App ID** 和 **App Secret**（Aily 应用的凭证可选），保存。
   保存前平台会先用这对凭证连一次飞书，连不上不会保存。保存后口令作废，这个页面随之关闭。
3. **马上用飞书账号登录**：完成首次配置之后、30 分钟内在同一个浏览器上第一个登录的人，自动成为运营管理员。
4. 在「同步管理」里点**测试连接**，看到「已连接」；等通讯录同步完（配置完成后自动开始，页面上能看到人数和部门数）。
5. 在「手动同步」里选**昨天**，点开始同步。任务成功后，「执行日志」里能看到各数据集写入了多少条，驾驶舱里出现数据。
6. 需要历史数据的话，再选一段更长的日期同步（比如近 30 天）。两个用量接口限频每秒 1 次，日期多时要等一会儿，可以离开页面。
7. 在「同步管理」里开启**每日定时同步**。

之后要换 App Secret、补 Aily 应用凭证，在「同步管理 → 修改凭证」里改；AI 洞察助手用的模型在「映射与推送 → AI 模型」里填。
凭证加密后存在数据库里，页面上只显示 App ID，不再显示任何密钥。

不想用页面的话，也可以把 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 写在 `.env` 里（这时不出现首次配置页面，运营管理员用 `AIUS_ADMINS` 指定；
open_id 在登录后的「接入管理 → 我的身份」里能看到）。两边都有时，以页面上保存的为准。

「已连接」只说明凭证可用、应用已发布；AI 用量权限有没有生效，要到第一次同步才知道。同步失败时，执行日志里有飞书返回的原始错误。

### 常见问题

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 测试连接失败 | App ID 或 App Secret 填错；应用还没发布 | 重新复制凭证（注意空格），确认最新版本已发布 |
| 连接成功但同步失败 | 两个 AI 用量权限没开通、没审核或还没生效 | 核对权限后重新发布应用版本 |
| 人员或部门显示成 ID | 通讯录权限或数据范围不够 | 补上用户、部门基础信息权限，数据范围设为全部员工，再同步通讯录 |
| 同步后没有数据 | 那天没有使用记录；或当天的数据还不完整 | 换一个确认有使用记录的完整自然日 |
| 应用显示成 ID | 没有配置 Aily 应用凭证，或应用已经被删除 | 在「映射与推送」里手工填名称 |
| 周报发不出去 | 应用没开机器人能力，或没有 `im:message:send_as_bot` | 开通后重新发布，再点「测试发送给我」 |

## 数据口径

- **总用量** = 人员用量日志 + 应用用量日志的消耗点数之和。
- **部门用量**按部门树向上汇总：一个部门的用量 = 它自己和所有下级部门成员的用量。人员所在的部门以用量日志上的为准（使用当时的部门），日志没带部门时按通讯录里的部门。
- **环比** = 和紧挨着的上一个同样长度的时间段相比。上一个时间段里只要有一天没同步成功过，就不计算（显示「—」），避免拿残缺的数据算出虚高的增长。
- **飞书项目、CodeM 沙箱应用**这两类没有单独的应用 ID，各算作一个应用。
- **折算费用** = 点数 × 单价（在「映射与推送」里设置，默认 0.05 元/点）。只是估算，不是账单。
- **豆包运营**只统计场景以「豆包工作」开头的人员用量（不含「豆包工作伙伴」）。
- **异常提醒**的规则：单日用量超过这段时间日均的 2 倍；部门或应用环比增长超过 50%；一个人占人员用量 25% 以上；某个人平均每次用量是整体平均的 3 倍以上。
- 用量日志是准实时的；统计详情是 T+1（当天的要到第二天才有）。日期都按北京时间的自然日划分。

## 同步是怎么做的

一个同步任务 = 一段日期。每天有四个数据集：人员日志、应用日志、人员统计详情、应用统计详情。

- **重复同步是安全的**：每个「日期 × 数据集」拉完整之后，在一个事务里整批替换，所以同一天同步多少次都不会有重复数据；拉到一半失败也不会留下半截数据。
- **一个数据集失败不影响其它的**，任务结束时状态是「部分成功」，对同一段日期再同步一次即可。
- **断点续跑**：每完成一个数据集记一次断点。服务重启、或者任务 30 分钟没有心跳时，从断点继续，最多自动续跑 3 次。
- **可以停止**：正在跑的任务拉完当前这一页就停，已经写入的数据保留。
- 遇到限频自动退避重试；两次调用之间至少间隔 1.1 秒。飞书建议避开凌晨 2 点左右的请求高峰，所以定时同步默认在 5 点。

## 开放接口与 MCP

在「接入管理」里生成**个人访问令牌**（`aius_...`）。令牌等同于你的身份：通过它能看到的数据和你在网页上能看到的一样，接口上没有「换一个人的 ID 就能看别人数据」的参数。

**开放接口**全部是只读的 GET，返回 JSON：

```bash
curl -H "Authorization: Bearer <令牌>" "https://ai-usage.example.com/openapi/v1/self-usage/summary?days=30"
```

一共 22 个，分三组：`/openapi/v1/self-usage/*`（所有人，只返回自己的数据）、`/openapi/v1/departments/*`（部门负责人和运营管理员）、
`/openapi/v1/analytics/*`、`/usage-logs`、`/usage-details`、`/quotas`、`/sync-runs`（运营管理员）。完整列表和说明在「接入管理」页面里。
时间范围用 `days`（默认 30）或 `start` + `end`（`YYYY-MM-DD`）。

**远程 MCP**（Streamable HTTP）挂在 `/mcp`，23 个只读工具（`aius_*`），AI 工具直接连，本机不用安装任何东西。生成令牌后页面会给出一段可以直接复制给
Claude Code、Cursor、Codex 的接入说明，例如：

```bash
claude mcp add --transport http --scope user ai-usage https://ai-usage.example.com/mcp --header "Authorization: Bearer <令牌>"
```

接好之后可以直接问「我上周用了多少点」「哪些部门的用量增长最快」。

## AI 洞察助手

运营管理员在「映射与推送 → AI 模型」里填上接口地址、API Key 和模型名（任何 OpenAI 兼容的 `/chat/completions` 接口；保存前会先试调一次）后，AI 门户里可以用自然语言提问。
平台先按提问人的数据范围算出一份分析数据（指标、排行、场景、异常），连同问题一起交给模型，模型只根据这份数据回答——所以普通用户问不出别人的用量。
没有配置模型时，提问会得到一份按数据直接整理的摘要。

## 数据与备份

所有数据在容器的 `/data` 卷里（一个 SQLite 文件 `aius.db`）。备份这个卷，或者：

```bash
docker compose exec ai-usage-insight python -c "import sqlite3; s=sqlite3.connect('/data/aius.db'); d=sqlite3.connect('/data/aius.db.bak'); s.backup(d)"
```

升级：`git pull && docker compose up -d --build`。升级前先备份。

服务只能起**一个进程**：同步任务、定时调度、通讯录同步都是进程里的后台线程。

## 开发

```bash
cd server
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest
python -m pytest -q            # 测试不连飞书
```

本地预览（不连飞书，演示数据，任意邮箱登录）：

```bash
AIUS_DEV_FAKE_LOGIN=1 AIUS_PUBLIC_URL=http://localhost:8090 AIUS_DATA_DIR=./data AIUS_ADMINS=admin@example.com \
  uvicorn --factory aius_server.app:create_app --port 8090
```

用 `admin@example.com` 登录是运营管理员；到「同步管理」同步一段日期，就有演示数据了。**`AIUS_DEV_FAKE_LOGIN` 绝对不能在生产环境打开。**

代码结构（`server/aius_server/`）：

| 文件 | 内容 |
|---|---|
| `feishu.py` | 飞书对接层：登录、通讯录、应用名称、两个 AI 用量接口、发卡片；以及开发 / 测试用的假飞书 |
| `sync.py` | 同步任务：按天整批替换、断点续跑、巡检、停止 |
| `directory.py` | 通讯录快照：部门树、成员、负责人 |
| `analytics.py` | 全部统计口径 |
| `access.py`、`core.py` | 角色与数据范围、登录态、表单提交的统一检查 |
| `pages.py`、`manage.py` | 分析页面、运营管理页面 |
| `openapi.py`、`remote_mcp.py` | 开放接口、远程 MCP（共用一套只读查询） |
| `quota.py`、`report.py`、`scheduler.py`、`insight.py` | 额度、周报、后台调度、洞察助手 |
| `templates/`、`static/` | 页面模板；`ui-kit.*` 是和其它控制台共用的设计系统，不要改，本站的样式写在 `app.css` |

## 安全说明

- 登录走飞书 OAuth；可以用 `FEISHU_TENANT_KEY` 限制只允许本企业的账号。
- 页面带严格的内容安全策略（没有内联脚本和样式）；改数据的请求校验登录、来源和角色。
- 个人访问令牌只存 SHA-256，明文只在生成时显示一次；可以设有效期、随时撤销，运营管理员可以撤销任何人的令牌。
- 飞书应用凭证和模型 API Key 加密后存在数据库里（密钥由 `AIUS_SECRET_KEY` 派生，所以只拿到数据库文件或它的备份解不开），不在页面和日志里出现。
  `AIUS_SECRET_KEY` 换了之后已保存的凭证就解不开了，要重新走一遍首次配置。
- 首次配置页面要凭服务器上的初始化口令才能提交，口令输错多次会被暂时锁定，配置完成后页面关闭。
- 普通用户看到的「所在部门」汇总有最小人数限制：除了自己，部门里用过 AI 的同事不到 3 位时不显示点数，避免反推出同事的个人用量。
- 内网部署时建议在前面挂一层 HTTPS 反向代理，并把端口绑定到内网网卡（`AIUS_BIND`）。
